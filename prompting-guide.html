11 ways to experiment with your prompt.

ACPE 2026 · Lab 2. Try one change, inspect the output, and keep what helps. These tips are adapted from the student notebook; the examples use synthetic clinical notes.

Try a prompting tip

Choose a topic or browse the cards below. Copy one idea into the playground, then check what changed.

01 / 11

Start with a clear task

Say what the model should extract. This is a zero-shot prompt: instructions without worked examples.

Edit: system_prompt

Extract the requested fields from the doctor's note.
Use only information documented in the note.
What should I check?

Did it miss a field or invent a fact? Write down one error before adding more instructions.

02 / 11

Give it a role

A role describes the job. Keep the extraction instructions as well.

Add to: system_prompt

Assume you are a clinical data abstractor.
Your job is to record what the note says.
What should I check?

Did the facts improve, or did only the tone change? A role does not make the model an expert.

03 / 11

Make the rules explicit

Explain the decisions the model keeps getting wrong. Use the field rules in the challenge brief.

Add to: system_prompt

Copy a dose only when an amount and mg or mcg are written.
Do not convert a tablet count into a dose.
What should I check?

Try a note with a written dose and one without. Clear rules should help both, not just your first example.

04 / 11

Separate instructions from the note

Keep your instructions in the system prompt and put each note inside clear boundaries.

Edit: user_prompt · keep {note}

Extract the information from this note.
<note>{note}</note>
What should I check?

The placeholder must stay in place: the preview and final run replace it with each new note. Tags clarify boundaries but are not a security guarantee.

05 / 11

Specify the output format

Ask for the same fields every time. The notebook supplies a JSON schema and displays the result as a table.

Add to: system_prompt

Return one JSON object with the requested fields.
Include short exact evidence quotes from the note.
What should I check?

A neat table can still contain wrong facts. Check the values and whether each quote supports them.

Structured outputs
06 / 11

Show an example

One-shot uses one worked example; few-shot uses several. Include both straightforward and tricky cases.

Add before <note> in user_prompt

Example note: [a short practice note]
Expected JSON: [your checked answer using all fields]

Now extract the next note:
<note>{note}</note>
What should I check?

Fill in the brackets yourself. Examples must be accurate. Do not use final-challenge notes as demonstrations; repeatedly tuning on practice cases can inflate your preview score.

Few-shot learning paper
07 / 11

Work through the decisions

Chain-of-thought prompting uses intermediate reasoning steps. Here, try a short checking sequence while keeping the final output structured.

Add to: system_prompt

Before answering, check who the note describes,
what happened, whether it was denied, and the final assessment.
Then return only the requested fields and evidence.
What should I check?

This checklist is a simple classroom adaptation of CoT. Check the final facts: more reasoning does not always improve them.

08 / 11

Ask for a final check

Target common omissions or unsupported claims.

Add at the end of: system_prompt

Recheck every field against the whole note.
Remove unsupported facts and fix any missed information.
Return only the final JSON.
What should I check?

Did it correct an error or repeat it? This is a single-call check. Full Self-Refine uses separate draft, feedback and revision calls.

09 / 11

Switch thinking mode

Thinking is a model setting, separate from the wording of your prompt.

Edit the playground parameters

thinking = True
temperature = 0.6
top_p = 0.95
top_k = 20
What should I check?

This is Qwen's suggested thinking preset. It changes several settings: compare thinking alone separately if you want to isolate its effect. Watch for longer runs and token-limit failures.

Qwen presets · Thinking mode
10 / 11

Test temperature and repeatability

With thinking off, compare sampling settings on the same note.

Edit one parameter at a time

temperature = 0.2  # Then try 0.7 or 0.9.
seed = 42          # Keep fixed first; later try 43 and 44.
What should I check?

Higher temperature allows more variation, not necessarily better answers. Keep top_p and top_k fixed at first. Repeated agreement is not proof of correctness.

11 / 11

Combine what helped

Keep changes that fixed a real error. Remove instructions that conflict.

Your route to the group challenge

1. Rerun the playground after your final edit.
2. Run the 20-note preview and read the field scores.
3. Improve your prompt and repeat the preview.
4. Freeze it, run all 80 notes, then submit.
How should I interpret the preview?

It is feedback on 20 practice notes, not a guaranteed final score. The final 80 notes are separate, and their answers remain with the instructor.
